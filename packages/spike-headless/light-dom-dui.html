Architecture proposal · DUI · companion to Headless DUI

Light DOM components

The same owned-file model without a shadow root, so your app's CSS can reach every element. Measured on one component, with the full source below.

Bottom line

This is a variant of the headless-controller model, not an alternative to it. Same controller, same prop bags, same markup. The component renders into the page instead of into a shadow root, and its styles are adopted into the document.

It removes the styling contract entirely. No ::part(), nothing to export, nothing for the library to anticipate. You write dui-select .trigger and it works.

It costs less encapsulation than expected. Ordinary page CSS that happens to share a class name does not affect the component. Only a deliberately more specific selector wins.

What changes

Four differences, and nothing else

The light-DOM select is the shadow-DOM one with four edits. The controller, the prop bags, the markup and the behaviour are byte-identical.

ChangeWhy
createRenderRoot()Returns this, so Lit renders into the element rather than a shadow root.
adoptedStyleSheetsstatic styles does nothing without a shadow root. The stylesheet is adopted into the document once, at module scope, with every selector prefixed by the tag name.
part= removedParts do nothing outside a shadow root. All eight were deleted — that is the point, not a loss.
base reset scopedThe shared reset contains * { box-sizing: border-box }. Adopting that document-wide from inside a component is unacceptable, so a scoped stand-in replaces it.

Using it

How a developer installs and uses this

// Install once. Behavior stays a dependency.
deno add @dui/controllers

// Your app owns the component file. Today you copy it in;
// later, `dui add select --light` writes it for you.
src/components/dui/select.ts

// Use it exactly like any element.
import "./components/dui/select.ts";

<dui-select .options=${fruits} value="apple"></dui-select>

Nothing about consuming the element changes. It is a custom element with properties and events, same as today. What changes is what you can do to it from your stylesheet.

Styling

The styling contract disappears

This is the difference that matters day to day. On the left, what you write today and what you cannot write at all. On the right, the same intent in light DOM.

Shadow DOM
/* Only exported parts are reachable. */
dui-select::part(trigger) { color: red; }
dui-select::part(listbox) { padding: 0; }

/* The chevron has no part, and
   ::part(x) y is invalid CSS. */
Light DOM
/* Ordinary selectors. All reachable. */
dui-select .trigger { color: red; }
dui-select .listbox { padding: 0; }
dui-select .icon { --icon-size: 10px; }

/* Nothing to export or anticipate. */

The third rule on the right is the one that could not be written before. The chevron carries no part, and a descendant selector may not follow ::part(), so through a shadow root there is no selector that reaches it. Closing that gap previously required a library release.

Encapsulation

What actually wins

Losing shadow DOM sounds like losing all protection. Measured, it is narrower than that. Leakage runs one way only: tag-prefixed selectors stop the component affecting the page — a plain .trigger element elsewhere on the page was untouched — while the page can reach in if it is specific enough.

Each row below is a real page rule tested against the component's own dui-select-l .trigger at (0,1,1):

Page ruleSpecificityResult
.trigger(0,1,0)No effect
div .trigger(0,1,1)No effect — ties go to the adopted sheet
.row .trigger(0,2,0)Overrides
.trigger !important—Overrides

Note the inversion, which is the useful part. In shadow DOM an outer-tree rule beats a :host rule on a tie. In light DOM with adopted stylesheets the component wins ties, so an app has to out-specify it deliberately. Accidental collisions lose; intentional overrides win. That is a better default than either sealed or wide open.

Migration

Converting a component is mechanical

A script rewrote the stylesheet. Every :host became the tag name; every other selector gained it as an ancestor.

/* Before — shadow DOM */          /* After — light DOM */
:host { ... }                      dui-select-l { ... }
:host([size="xs"]) .trigger { }    dui-select-l[size="xs"] .trigger { }
.popup:popover-open { }            dui-select-l .popup:popover-open { }

/* 51 selector lines. Zero needed hand editing. */

51 selector lines rewritten, zero needing hand editing. If the library moves to light DOM, the conversion is a codemod rather than a rewrite — but it has to happen before apps own their files, because after that the rewrite is theirs to run.

Trade-offs

What it costs

CostDetail
::part() breaksAnyone styling through parts rewrites to plain selectors. A one-time edit for an app that owns its file; a breaking change for the library's ready-made components.
The shared resetCannot be adopted document-wide from a component. Each light-DOM component needs a four-line scoped stand-in, which is easy to forget.
Real encapsulation is goneA determined or careless page rule can reach in. That matters most for embedding DUI in a host page you do not control — which is the case the shadow root was there for.
Markup is now publicYour class names become the contract, whether you document them or not. In shadow DOM they were private by accident; here that has to be a decision.
Evidence

What is proven and what is not

Proven

  • Exact parity. 0 differing pixels against the shadow-DOM owned select across default, size="xs", disabled and restyled rows.
  • Behaviour is untouched. The popup opens in the light DOM and positions correctly, keyboard selection works, form association survives.
  • The restyle is equivalent. dui-select-l .trigger produced the identical computed result to ::part(trigger) on the shadow versions.
  • The conversion is scriptable. 51 selector lines, zero manual.

Not proven

  • Components that slot your content. Select slots nothing. A component that accepts arbitrary children would exercise the leakage question far harder than this test did.
  • The embedding story. DUI's use inside host pages is exactly the case shadow DOM protects, and nothing here measures what breaks.
  • Anything beyond select. One component, one variant, one afternoon.

 * `<dui-select-l>` — the same owned select, rendered into the LIGHT DOM.
 *
 * Step 3 of the four-step plan: does dropping shadow DOM make the owned-file
 * model better? Same controller, same spread directive, same markup. The only
 * differences are where the element renders and how its styles get applied.
 *
 * What changed, and nothing else did:
 *
 *   1. `createRenderRoot()` returns `this`, so Lit renders into the element.
 *   2. `static styles` does nothing without a shadow root. The stylesheet is
 *      adopted into the document once, at module scope, with every selector
 *      prefixed by the tag name. That prefixing was fully mechanical: 51
 *      selector lines, `:host` -> `dui-select-l`, everything else -> descendant.
 *      Zero needed hand editing.
 *   3. `part=` attributes are gone. They do nothing outside a shadow root —
 *      which is the point: a consumer writes `dui-select-l .trigger` instead of
 *      `::part(trigger)`, so there is no export ceremony and nothing to publish.
 *   4. The shared `base` reset could not come along. It contains
 *      `* { box-sizing: border-box }`, and adopting that into the document from
 *      a component would be an unacceptable side effect. A scoped equivalent is
 *      at the top of the stylesheet instead. See FINDINGS.
 */

export class DuiSelectL extends LitElement {
  static tagName = "dui-select-l" as const;

  /** Render into the light DOM. Everything below is now ordinary page CSS. */
  protected override createRenderRoot(): HTMLElement {
    return this;
  }

  static formAssociated = true;
  #internals: ElementInternals = this.attachInternals();

  override willUpdate(): void {
    this.#internals.setFormValue(this.value);
  }

  @property({ attribute: false })
  accessor options: SelectOption[] = [];

  @property({ type: String })
  accessor value = "";

  @property({ type: String })
  accessor placeholder = "Select...";

  @property({ type: Boolean, reflect: true })
  accessor disabled = false;

  @property({
    type: Boolean,
    attribute: "align-item-to-trigger",
    reflect: true,
  })
  accessor alignItemToTrigger = true;

  @property({ type: String })
  accessor name = "";

  @property({ type: Boolean, reflect: true })
  accessor badge = false;

  #select = new SelectController(this, {
    getOptions: () => this.options,
    getValue: () => this.value,
    getPlaceholder: () => this.placeholder,
    getDisabled: () => this.disabled,
    getAlignItemToTrigger: () => this.alignItemToTrigger,
    onChange: (value, option) => {
      this.value = value;
      this.dispatchEvent(
        new CustomEvent("value-change", {
          detail: { value, option },
          bubbles: true,
          composed: true,
        }),
      );
    },
  });

  get #selectedIndex(): number {
    return this.#select.options.findIndex((o) => o.value === this.value);
  }

  override render(): TemplateResult {
    const c = this.#select;

    return html`
      <div class="trigger" ${spread(c.triggerProps)}>
        <span class="icon">
          <dui-icon>
            <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none"
              stroke="currentColor" stroke-width="2" stroke-linecap="round"
              stroke-linejoin="round">
              <path d="m6 9 6 6 6-6" />
            </svg>
          </dui-icon>
        </span>
        <span class="value" ${spread(c.valueProps)}>
          ${c.hasValue ? c.displayValue : this.placeholder}
        </span>
        ${this.badge && c.hasValue
          ? html`<span class="badge">${
            this.#selectedIndex + 1
          }/${c.options.length}</span>`
          : nothing}
      </div>

      <div class="popup" ${spread(c.popupProps)}>
        <dui-scroll-area ${spread(c.scrollerProps)}>
          <div class="listbox" ${spread(c.listboxProps)}>
            ${repeat(
              c.options,
              (option) => option.value,
              (option, index) => this.#renderItem(option, index),
            )}
          </div>
        </dui-scroll-area>
      </div>
    `;
  }

  #renderItem(option: SelectOption, index: number): TemplateResult {
    const c = this.#select;
    const isSelected = option.value === this.value;

    return html`
      <div class="item" ${spread(c.itemProps(index))}>
        <span class="indicator">
          ${isSelected
            ? html`
              <dui-icon>
                <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none"
                  stroke="currentColor" stroke-width="2" stroke-linecap="round"
                  stroke-linejoin="round">
                  <path d="M20 6 9 17l-5-5" />
                </svg>
              </dui-icon>
            `
            : nothing}
        </span>
        <span class="item-text" ${spread(c.itemTextProps)}>${option
          .label}</span>
      </div>
    `;
  }
}

customElements.define(DuiSelectL.tagName, DuiSelectL);
